Как управлять сайтом

Каталог, портфолио и цены редактируются в одном месте. Для обычных правок не нужны Python, Git и компьютер разработчика.

1. Вход

Откройте панель управления и нажмите «Войти через GitHub». Публикация разрешена только GitHub-пользователям, у которых есть право записи в репозиторий Amanich2024/moduldom.

  1. Владелец репозитория заранее добавляет сотрудника через GitHub Settings → Collaborators. Панель не выдаёт права доступа самостоятельно.
  2. Сотрудник открывает создание fine-grained token в своём GitHub.
  3. Выбирает владельца репозитория, Only select repositories → moduldom. Выбирает срок действия, например 30 дней.
  4. В Repository permissions: Contents — Read and write, Actions — Read-only. Не давайте доступ ко всем репозиториям.
  5. Копирует созданный ключ в поле входа админки и нажимает «Проверить доступ».

Это текущий способ авторизации для GitHub-размещения, не вход с обычным паролем сайта. Ключ не хранится между сеансами и не включается в копии. После обновления вкладки нужен повторный вход. После окончания работы нажмите «Выйти». В случае потери ключа отзовите его в GitHub.

2. Изменить дом или добавить новый

Откройте «Типовые дома» → «Изменить». Укажите название, габариты, площади, комнаты, цены, фотографии дома и два плана. Новый дом удобно создать кнопкой «Копия», затем заменить данные и изображения.

Новые дома создаются как черновики. После проверки выберите видимость «Опубликован». Габариты и площади указываются отдельно: не складывайте площадь террасы с площадью дома в одном поле. Название карточки можно задать по согласованному правилу общей площади.

«Построенные дома» — отдельный раздел для реализованных объектов. Первая опубликованная запись становится главным домом настольного сайта. Кнопки ↑ ↓ меняют общий порядок. Даты из параметра «Сдан» не выводятся поверх фотографии автоматически.

3. Фотографии и планы

Поддерживаются JPG, PNG, WebP до 20 МБ на файл. Панель уменьшает изображение до 2400 пикселей по длинной стороне и сохраняет WebP. Можно менять порядок, подписи и обложку. На телефоне также можно загружать фотографии.

До публикации новые файлы находятся в памяти вкладки. Если закрываете её — скачайте резервную копию с фотографиями. Обычный автоматический черновик браузера сохраняет поля, но не новые файлы.

4. Цены и комплектации

В разделе «Цены» меняются обе комплектации. Массовое изменение сначала показывает «было → стало» и округляет новые суммы до тысячи рублей. Оно применяется ко всем опубликованным типовым домам.

В разделе «Комплектации» редактируются общие описания. Слова в фигурных скобках {doors}, {windows}, {terrace} — подстановки, их сохраняйте. Пустое значение означает отсутствие отделки по принятому шаблону.

5. Архив, предпросмотр и публикация

  1. Подготовьте правки. Они ещё не видны покупателям.
  2. Откройте предпросмотр карточки и проверьте изображения, план и цены.
  3. Нажмите «Проверить и опубликовать». Посмотрите список изменений и подтвердите.
  4. Панель сохранит данные и фотографии одним коммитом, затем GitHub проверит каталог и соберёт все версии.
  5. Дождитесь сообщения об успешной публикации. При ошибке сборки опубликованный сайт останется на предыдущей версии.

Проверить публикацию в GitHub Actions ↗

При одновременном редактировании панель не перезапишет чужую новую версию. Скачайте свои правки, перечитайте данные и объедините изменения.

«В архив» убирает дом с сайта после публикации, но сохраняет его материалы. «Восстановить» возвращает его как черновик. Постоянное удаление исходных файлов из интерфейса намеренно отсутствует, чтобы не разрушать старые версии.

6. Резервные копии

«Скачать резервную копию» сохраняет каталог и новые неопубликованные изображения. Для полного восстановления сайта дополнительно нужен репозиторий GitHub со всеми уже опубликованными изображениями и кодом.

В разделе «История и копии» можно загрузить копию или выбрать прежнюю версию данных из истории GitHub. Это создаёт черновик: перед публикацией проверьте его. Старые изображения не удаляются при обычной работе.

Черновики и архив не показываются в каталоге, но не являются конфиденциальным хранилищем: репозиторий и исходный файл каталога сейчас публичны. Не добавляйте личные сведения заказчиков, пароли и документы.

7. Что не меняется этой админкой

  • Новый дом в каталоге не создаёт новый инженерный тип в конструкторе. Новые правила стен, крыши и планировок добавляет разработчик.
  • Панель не является CRM, не обрабатывает оплаты и не создаёт аккаунты покупателей.
  • Тексты редактируются в существующих блоках; создание нового дизайна страницы требует разработки.
  • Предпросмотр показывает карточку, а не копию всех эффектов сайта. Финальный результат проверяется после сборки.
  • Настройки Метрики, владельца Telegram-бота и домена меняются в соответствующих сервисах.

Передача руководству

Передайте компании права владельца репозитория или перенесите его в организацию компании; домен, аккаунт размещения, Telegram-бота и Метрику. При переносе репозитория нужно обновить REPO в admin.js и настройки Pages. Сохраните полный архив репозитория вне GitHub. Назначьте минимум двух владельцев доступа.

Адрес панели: https://zagorodnaya-studiya.ru/admin/. Она открывается в браузере Windows, Mac и телефона.
